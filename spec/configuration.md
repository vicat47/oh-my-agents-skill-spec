# 配置契约

采用 [ADR-001](../docs/adr/001-single-project-toml.md)：一个消费项目维护一份项目 TOML，以 `#:schema` 关联一个项目总 JSON Schema。基础领域定义平台标识、区域和环境，业务领域定义服务实例及操作指南，skill 定义自己的专属字段。同一共享字段只由一处定义。

- 装配工具在初始化时生成总 Schema，添加 skill 时更新该入口，保留 TOML 中的已有值。源 Schema 可复用；统一入口不要求物理单文件打包。
- 配置型 skill 必须说明读取的配置节、字段来源，提供最小样例，自行解析并校验。业务值写入项目配置；生成的 Schema 不存实际配置值。全局默认值只在首次初始化项目清单时应用，显式空值不等于缺失；全局作用域的设置仍读全局。
- 凭据绑定到具体服务实例，项目配置只存引用。缺少绑定时报告缺项，不向其他环境、服务或账号回退。

**验收：** 加装一个 skill 后仍编辑原文件，既有平台配置保留，新字段可被编辑器识别。绕过编辑器直接执行时，缺少必填字段同样应在访问目标前被指出。项目 TOML 的固定文件名、生成器及引用的分发方式不在本版定案范围。
