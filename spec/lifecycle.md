# 生产生命周期

每个阶段用可观察的结果判断完成，不要求为每步创建文件。

| 阶段 | 开发 Agent 的工作 | 通过条件 |
|---|---|---|
| 选场景 | 取得真实请求，检查现有 skill 是否已覆盖 | 能给出适用请求和容易误触发的相似请求，并说明为何新建或改进已有 skill |
| 定契约 | 写出输入、输出、适用目标、动作、失败与副作用 | 实现前已有可判定的正例、反例和异常例 |
| 制作 | 写 `SKILL.md`，按需补脚本、Schema 和资源 | 依赖与入口可由包内说明找到 |
| 验收 | 分别检查是否选对 skill、选对后是否执行正确 | 正例产生预期结果；反例不发生范围外动作；异常例停止并说明原因 |
| 交付 | 从安装位置、在消费项目上下文中复验 | 使用者只需包、声明的依赖和项目输入，无需作者的会话或绝对路径 |
| 演进与退役 | 把现场失败转成回归用例；说明升级或移除的影响 | 旧问题可复现，配置、运行状态与用户结果的保留方式可知 |

验收记录必须区分脚本测试与 Agent 选用测试。验证交接时，给未参与开发的 Agent 原始请求、候选 skill 与必要的项目输入，保留预期答案供验收者比对。尚未进行的验证标为待验证。
